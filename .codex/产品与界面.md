# 产品与界面规则

## 1. 产品边界

### 1.1 Components：免费组件库

只收录以下三类，不做 Button、Input、Select 等基础原子组件：

- **Business Components**：登录、搜索筛选、上传、结算、资料编辑、AI 对话等完整业务能力。
- **App UI**：预算、Todo、设置、聊天、统计、日历、笔记等完整业务页面或界面。
- **Motion Components**：Scroll Reveal、Card Stack、数字滚动、页面过渡、Bottom Sheet、3D Tilt、Marquee 等动画与交互效果。

每个组件至少包含：效果预览、Prompt、技术栈、功能或交互说明、标签和分类；适合时提供在线 Demo。

组件内容永久免费，主要承担作品展示、Prompt 传播、SEO 和向 Template 导流的职责。

### 1.2 Templates：完整模板库

Template 是能够作为完整产品交付的成品项目，例如企业官网、Landing Page、Blog、工具网站、Web App、PWA、SaaS。

每个模板至少展示：

- 完整效果图和在线 Demo；
- 页面与功能列表；
- 技术栈；
- 使用到的 Components；
- 不同交付技术路线；
- 各路线参考报价；
- 微信 / Email 联系方式。

不做在线支付、购物车和订单系统。

## 2. 模板交付路线

同一个 Template 可以提供多套技术方案，不使用含糊的“基础版 / 高级版”代替技术边界。

### Static / 纯静态

适合企业展示站、Landing Page、工具站、无账号体系的小型 PWA。典型能力包括 React / Next.js Static Export、LocalStorage / IndexedDB、PWA 和静态托管。

### Full Stack / 全栈

适合账号体系、云端数据、API、多端同步。可采用 Next.js、PostgreSQL、Auth、独立后端或 Serverless。

### Admin / 后台管理

面向正式运营产品，可包含用户管理、内容管理、数据管理、Dashboard、RBAC 和操作日志。

模板详情页必须说明各路线的能力边界、适用场景和参考报价差异。

## 3. Components 与 Templates 关联

两类内容必须支持双向关联：

```text
Component → Used in Templates
Template  → Built with Components
```

免费组件负责流量和能力展示，完整模板负责商业转化。

## 4. UI 方向

默认采用黑色 / 深灰视觉体系：

- 大面积深色负空间；
- 卡片式 Gallery；
- 轻量渐变和高光；
- 大标题、大预览图、小面积品牌色；
- 强调作品截图和真实 Demo，减少无意义装饰；
- 整体接近现代 SaaS / Developer Tool；
- 桌面端优先展示，同时保证移动端完整可用。

首页只需要清晰表达两件事：

```text
Components
免费业务组件 / App UI / Motion + Prompt

Templates
完整网站模板 + 多种技术路线 + 参考报价
```

作品优先，不堆砌营销文案。

## 5. 页面规划

- `/`：Hero、精选 Components、三类组件入口、精选 Templates、技术路线简介、联系 CTA。
- `/components`：免费组件 Gallery，支持分类、标签和搜索。
- `/components/[slug]`：Preview、Demo、Prompt、Copy Prompt、Stack、Features、Related Templates。
- `/templates`：完整模板 Gallery。
- `/templates/[slug]`：效果、Demo、页面、功能、技术栈、Related Components、交付路线、参考报价、联系 CTA。
- `/pricing`：技术路线和报价说明，不是购买套餐页。
- `/contact`：微信二维码、微信号（如需要）、Email、可承接范围。

## 6. V1 明确不做

- 用户注册 / 登录；
- 收藏云同步；
- 在线支付；
- 订单系统；
- CMS；
- 评论系统；
- 用户投稿；
- 实时数据库驱动页面。
