# 非经营性备案展示规则

## 背景

- 主域名已完成非经营性 ICP 备案（个人博客）。
- VibeCode 将作为该主域名下的二级域名部署，网站设计与内容应持续符合当前备案及实际服务性质。
- 网站展示 VibeCode 组件与模板。
- 组件免费，用户可查看效果、复制 Prompt 并自行使用。
- 模板作为作品、案例和产品设计展示，不在网站内直接交易。
- 如网站未来实际业务性质发生变化，应先重新核对备案、许可及相关合规要求，再调整网站能力。

> 法规基线：《互联网信息服务管理办法》区分经营性与非经营性互联网信息服务，并规定互联网信息服务提供者应按照经许可或备案的项目提供服务，非经营性互联网信息服务提供者不得从事有偿服务。

## 核心设计原则

> 网站必须是一个“作品展示橱窗”，而不是“服务柜台”。展示可以，但不要“招呼”。

所有首页、组件页、模板页、搜索页、关于页、SEO 文案和后续新增页面，都必须遵循该原则。

## 必须遵守的规则

### 1. 禁止出现交易内容

网站页面中禁止出现：

- 任何价格、金额、报价数字；
- “购买”“付费”“收费”“下单”等直接交易词；
- “获取完整版”“解锁”“高级版”等暗示付费后获取内容的表述；
- “定制请私聊”等服务招揽文案；
- “立即咨询”“添加客服”“联系我拿模板”等明确引导转化的按钮或文案；
- 任何暗示“需要付费才能获取”的表述；
- 购物车、订单、支付、套餐购买、询价表单等交易能力。

模板不得通过“参考价格”“起步价”“联系报价”等方式变相展示价格。

### 2. 联系方式位置

联系方式只能作为网站运营者的基本信息展示，放置在常规位置，例如：

- 关于页面；
- 页脚的联系方式栏目。

联系方式不得作为某个 Component 或 Template 的获取入口。

禁止：

- 在模板卡片放置联系方式按钮或链接；
- 在模板详情页放置联系方式按钮或链接；
- 在组件详情页通过“完整模板”区域引导联系；
- 使用悬浮客服、微信咨询、立即沟通等强转化入口。

### 3. Component 页面

Component 定位为免费公开内容。

允许展示：

- Preview / Demo；
- Prompt；
- Copy Prompt；
- 组件说明；
- Features；
- 技术栈；
- 适用场景；
- 参考来源；
- Related Templates。

Related Templates 只能用于作品之间的内容关联，例如“使用该组件的完整模板”“相关作品”，不得附带价格、购买、咨询、获取等交易信息。

### 4. Template 页面

Template 定位为完整作品 / 产品案例展示，而不是商品销售页。

允许展示：

- 完整 Preview；
- Live Demo；
- 页面列表；
- 功能说明；
- 技术方案；
- 技术栈；
- 设计说明；
- Related Components；
- 不同实现方式的技术差异。

禁止把实现方式包装为可购买套餐。

例如可以展示：

- 纯静态实现；
- 全栈实现；
- 带后台管理的实现；

但只能解释技术能力、架构差异和适用场景，不展示价格，不使用“轻量版 / 标准版 / 商业版”等容易形成商品档位的销售表达。

### 5. CTA 规则

允许的 CTA 应属于内容浏览和产品体验行为，例如：

- 查看 Demo；
- 全屏预览；
- 复制 Prompt；
- 查看组件；
- 查看模板；
- 查看相关作品；
- 查看技术实现。

禁止交易或服务转化型 CTA，例如：

- 购买；
- 获取；
- 咨询；
- 联系定制；
- 我要这个模板；
- 获取源码；
- 立即拥有。

### 6. 首页

首页以发现内容和浏览作品为目标。

首页可以：

- 展示热门 / 最新 Components；
- 展示精选 Templates；
- 提供分类、筛选、搜索；
- 介绍 VibeCode 的内容定位。

首页不得：

- 展示报价；
- 宣传定制服务；
- 设置“咨询”“联系购买”等商业 CTA；
- 使用限时、优惠、套餐、成交等销售语言。

### 7. 数据模型约束

业务 Schema 不应以交易模型为核心。

V1 不设计：

- price；
- originalPrice；
- paid；
- purchaseUrl；
- checkoutUrl；
- order；
- sku；
- planPrice；
- contactForPurchase。

Template 中如需描述不同技术实现，使用中性的技术模型，例如：

```ts
interface TemplateImplementation {
  id: string
  stack: string[]
  capabilities: string[]

  content: Record<Locale, {
    name: string
    description: string
    suitableFor?: string
  }>
}
```

其职责是解释“这个作品可以采用哪些技术方式实现”，而不是定义可购买 SKU。

### 8. 后续设计门禁

新增或修改页面时，提交前必须检查：

1. 是否出现价格或金额；
2. 是否出现交易诱导词；
3. 是否存在从模板直接进入联系方式的路径；
4. 联系方式是否仅位于常规运营者信息位置；
5. Template 是否仍然表现为作品展示，而非商品销售；
6. CTA 是否仅用于浏览、体验、复制和内容导航；
7. 是否新增了具有交易含义的数据字段。

若任一项不满足，不得按当前非经营性展示规则发布。

## 说明

本文件是 VibeCode 当前产品与界面设计的项目约束，不替代针对具体业务形态的正式法律意见。

如果未来网站实际提供有偿互联网信息服务、在线交易、明确服务招揽或其他与当前备案性质不同的业务，应先核对并完成所需备案/许可调整，再修改本规则和产品能力。
