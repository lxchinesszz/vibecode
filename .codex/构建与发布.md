# 构建与发布规则

## 1. 发布链路

固定主链路：

```text
本地开发
   ↓
git push
   ↓
GitHub Actions
   ↓
pnpm install
   ↓
数据生成
   ↓
Next.js build / Static Export
   ↓
out/
   ↓
又拍云对象存储 / CDN
```

GitHub 是代码和内容源，构建阶段生成标准化数据和静态页面，又拍云只承载最终静态产物。

## 2. GitHub Actions

CI 最低要求：

```bash
pnpm install --frozen-lockfile
pnpm build
```

如果数据生成独立于 build：

```bash
pnpm generate:data
pnpm build
```

部署阶段只上传最终 `out/`，不要把 `.next/`、源码目录或依赖目录作为站点产物上传。

## 3. Static Export 门禁

任何页面、依赖或框架能力的引入，都必须保证 `output: "export"` 可继续工作。

如果新需求必须依赖运行时服务端能力，不能直接破坏当前部署链路；应先更新需求档案和技术方案，并明确新的部署边界，经确认后再实施。

## 4. 又拍云同步

同步逻辑优先复用或抽取 `zero-blog` 已验证方案。

长期要求：

- manifest 对比；
- 增量上传；
- 合理并发；
- 删除远端失效文件；
- 为 HTML、JS/CSS、图片等设置合适缓存策略；
- 必要时刷新 CDN。

禁止每次无差别全量上传大量未变化资源。

## 5. 发布状态

以下状态必须区分：

- 本地代码完成；
- 测试通过；
- 构建成功；
- Git 已提交；
- 已推送 GitHub；
- GitHub Actions 成功；
- 又拍云同步成功；
- 线上地址验证成功。

只有最后的线上链路实际完成并验证后，需求状态才能记录为“已发布”。
