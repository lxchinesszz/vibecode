# 多语言规则

## 1. 定位

VibeCode 从 V1 开始具备多语言能力。首批正式支持：

- `zh`：中文
- `en`：English

架构必须允许后续继续增加其他 Locale，不得把中文或英文硬编码为唯一语言。

多语言分为两层：

1. **UI 国际化**：导航、按钮、状态、分类名称等网站公共文案。
2. **内容国际化**：Component、Template 等业务内容。

两者必须分离管理。

## 2. URL 规则

所有可索引页面使用语言前缀：

```text
/zh
/en

/zh/components/saas-hero
/en/components/saas-hero

/zh/templates/ai-saas
/en/templates/ai-saas
```

禁止使用 `?lang=en` 作为主要语言路由方案。

根路径 `/` 只负责进入默认或匹配语言版本，不作为独立重复内容页。

每个语言页面必须拥有独立 canonical，并正确生成对应语言的 sitemap / alternate / hreflang 信息。

## 3. Locale

统一定义：

```ts
export const locales = ["zh", "en"] as const

export type Locale = (typeof locales)[number]

export const defaultLocale: Locale = "zh"
```

业务代码不得散落 `"zh"`、`"en"` 判断，应通过统一 Locale 配置扩展。

## 4. UI 文案

公共界面文案单独维护，例如：

```ts
const messages = {
  zh: {
    components: "组件",
    templates: "模板",
    copyPrompt: "复制 Prompt",
    fullscreen: "全屏预览",
    preview: "预览",
    suitableFor: "适合",
    implementation: "实现",
  },
  en: {
    components: "Components",
    templates: "Templates",
    copyPrompt: "Copy Prompt",
    fullscreen: "Fullscreen",
    preview: "Preview",
    suitableFor: "Best for",
    implementation: "Implementation",
  },
}
```

页面组件禁止直接硬编码可翻译的公共 UI 文案。

## 5. 内容模型原则

系统标识与可翻译内容必须分离。

以下字段属于稳定系统数据，不随语言变化：

- `slug`
- `category`
- `tags`
- `stack`
- Component / Template 关联 ID
- 状态、排序等管理字段

例如分类内部存：

```text
hero
pricing
login
navigation
```

显示层再根据 Locale 转换为“首屏 / Hero”等用户语言。

禁止直接把“首屏”“价格”等中文显示名称作为系统分类 ID。

## 6. Component 多语言模型

Component 推荐模型：

```ts
interface LocalizedComponentContent {
  name: string
  description: string

  prompt: {
    content: string
  }

  features: {
    name: string
    description?: string
  }[]

  suitableFor: string[]
}

interface VibeComponent {
  slug: string
  category: string
  tags: string[]

  content: Record<Locale, LocalizedComponentContent>

  preview: {
    type: "live" | "image" | "video"
    url: string
    cover?: string
  }

  stack: string[]
  relatedTemplates: string[]

  references?: {
    name: string
    url?: string
    type?: "inspiration" | "source" | "product"
  }[]

  status: "draft" | "published"
  sort?: number
}
```

## 7. Prompt

Prompt 是 VibeCode 的核心内容资产。

中文和英文 Prompt 独立维护：

```text
content.zh.prompt
content.en.prompt
```

禁止把运行时机器翻译作为正式 Prompt 内容来源。

不同语言的 Prompt 可以根据 Coding Agent 的表达习惯分别优化，不要求逐句对应。

## 8. Preview

Preview 默认是语言无关资产：

```ts
preview: {
  type: "live",
  url: "/demos/saas-hero"
}
```

`/zh/components/saas-hero` 与 `/en/components/saas-hero` 默认共用同一 Preview。

只有 Demo 本身确实存在语言差异时，才允许扩展 localized preview。V1 不提前增加这一复杂度。

## 9. Template

Template 必须遵循与 Component 相同的原则：

```text
稳定系统字段
+
content.zh
+
content.en
+
共享 Preview / Demo / 技术数据
```

Template 的 name、description、pages、features、交付说明、适用对象等面向用户的文字进入 Locale Content；slug、分类 ID、技术栈、关联组件等保持语言无关。

具体 Template Schema 在模板详情页设计确认后再固化，避免提前锁死尚未确认的商品模型。

## 10. 搜索与生成数据

构建阶段生成的数据必须保留 Locale 维度。

搜索索引至少能够区分：

```text
zh + components
en + components
zh + templates
en + templates
```

搜索默认只返回当前 Locale 内容，除非产品后续明确增加跨语言搜索。

静态生成阶段必须为所有已发布 Locale × 页面生成对应路径。

## 11. SEO

多语言页面至少满足：

- 每个 Locale 独立 URL；
- title / description 使用当前语言内容；
- canonical 指向当前语言规范 URL；
- 提供 alternate / hreflang；
- sitemap 包含语言页面；
- Open Graph 使用当前语言文案；
- 不把不同语言页面视为重复内容。

## 12. V1 边界

V1 只正式维护中文和英文。

暂不做：

- 自动机器翻译作为正式内容；
- 用户自定义语言；
- 每个 Demo 强制维护多语言版本；
- 跨语言全文搜索；
- 为未来语言复制大量空内容。

新增语言时，应主要通过增加 Locale 配置和对应内容实现，不应修改 Component / Template 核心业务结构。
